# Technitium DNS Server

Конфигурация Technitium DNS Server для Docker Compose. DNS-запросы доступны на порту `53` по UDP и TCP, а веб-интерфейс опубликован через Traefik по HTTPS.

## Требования

- Docker с плагином Docker Compose (`docker compose`)
- Внешняя Docker-сеть `proxy`, подключённая к Traefik
- DNS-имя, указанное в `DNS_SERVER_DOMAIN`, направлено на Traefik

Compose подключает сервис к уже существующей внешней сети `proxy` — создать её автоматически Compose не сможет. В текущей конфигурации используется подсеть `192.168.200.0/24`, а адрес шлюза Docker-сети — `192.168.200.1`. Если такой сети ещё нет, создайте её:

```bash
docker network create \
  --driver bridge \
  --subnet 192.168.200.0/24 \
  --gateway 192.168.200.1 \
  proxy
```

Подсеть `192.168.200.0/24` содержит адреса от `192.168.200.1` до `192.168.200.254`; `.1` зарезервирован как шлюз сети. Перед созданием проверьте, что эта подсеть не пересекается с LAN/VPN-подсетями хоста и другими Docker-сетями. При конфликте выберите свободную приватную подсеть и укажите её вместе со шлюзом из этой же подсети в команде выше. Traefik должен быть подключён к сети с именем `proxy`.

Проверить параметры уже созданной сети можно так:

```bash
docker network inspect proxy
```

Если сеть `proxy` уже существует, повторно создавать её не нужно; проверьте, что её подсеть и шлюз соответствуют вашей конфигурации.

## Настройка

1. Создайте локальный файл параметров Compose и задайте уникальный пароль администратора:

   ```bash
   cp .env-example .env
   ```

   Сгенерировать пароль можно командой:

   ```bash
   openssl rand -base64 32
   ```

   Запишите результат в `DNS_SERVER_ADMIN_PASSWORD` в файле `.env`. Этот файл исключён из Git. Не запускайте сервис с пустым паролем.

2. При необходимости измените в `.env`:

   - `VERSION` — версию образа; используйте конкретный тег для предсказуемых обновлений.
   - `TECHNITIUM_BIND_IP` — IP-адрес хоста для DNS-портов. Значение по умолчанию `0.0.0.0` открывает порт на всех интерфейсах; для ограничения доступа укажите IP нужного интерфейса.
   - `DNS_SERVER_DOMAIN` — домен веб-интерфейса. Создайте соответствующую DNS-запись и убедитесь, что Traefik подключён к сети `proxy`.

3. При необходимости измените DNS-forwarders в блоке `environment` файла `docker-compose.yaml`. Сейчас настроены `1.1.1.1` и `9.9.9.9` по протоколу UDP.

   - `DNS_SERVER_FORWARDERS` — адреса upstream DNS-серверов через запятую.
   - `DNS_SERVER_FORWARDER_PROTOCOL` — протокол запросов к upstream-серверам, например `Udp`.

## Запуск и проверка

Из каталога этого проекта:

```bash
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs -f technitium
```

Веб-интерфейс: `https://<DNS_SERVER_DOMAIN>` (по умолчанию `https://dns.int.devhomelab.site`). Порт `5380` также опубликован только на loopback хоста для локальной диагностики.

Проверить DNS можно с хоста, на котором запущен контейнер:

```bash
dig @127.0.0.1 example.com
dig +tcp @127.0.0.1 example.com
```

Если DNS нужен другим устройствам, разрешите входящий TCP/UDP порт `53` только из доверенной локальной сети. Не публикуйте открытый рекурсивный DNS-сервер в интернет.

## Данные и обновление

Настройки и данные сервера хранятся в Docker volume `technitium_config` и сохраняются при пересоздании контейнера:

```bash
docker compose pull
docker compose up -d
```

Перед обновлением сохраните резервную копию volume. `docker compose down` оставляет volume на месте; `docker compose down -v` удаляет его вместе с данными.
